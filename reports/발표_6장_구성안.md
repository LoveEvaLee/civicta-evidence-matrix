# 팀 발표용 6장 구성안 (발표시간은 수업 지시 기준으로 조절)

## 슬라이드 1 — 문제제기
**시민은 기술영향평가에 참여하지만, 참여한 의견의 정책 반영 과정까지 확인할 수 있는가?**
과학기술정책과 HCI가 다른 지점에서 같은 문제를 다룸.

## 슬라이드 2 — 연구문제와 이론적 접점
정책 관점: 의제설정→숙의→정책결정→집행/평가
HCI 관점: 접근성→설명→상호작용→피드백 추적→신뢰

## 슬라이드 3 — 도구 설계
문헌 메타데이터(CSV) → 별도 `rules.js` 코드북 → 매트릭스/문헌 목록/내보내기
문헌 진위와 내용 분류는 사람의 원문 검토가 필요함.

## 슬라이드 4 — 실시간 시연
**가상 예시 12건** → 5×4 매트릭스 → 셀 선택으로 문헌을 확인 → Markdown 보고서
가상 문헌을 실제 연구처럼 표현하지 않음.

## 슬라이드 5 — GitHub 협업과 사람 검토
A/B 분업 → 이슈/브랜치/각자 PR → 교차 리뷰 → 수정/승인 → 병합
오류가 발견된 사례와 재현한 검산 결과가 가장 중요.

## 슬라이드 6 — 정책연구 함의 및 후속계획
이 도구로 특정 문헌 표본의 근거 분포를 살펴본다.
후속 연구는 실존 문헌의 원문 코딩·서지검증·검색 범위 명시 후 수행한다.
**질문:** 데이터 기반 기술영향평가에서 어떤 판단은 자동화할 수 있고, 어떤 판단은 연구자가 남겨야 하는가?
