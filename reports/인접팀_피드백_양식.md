- 직접 입력한 자료 유형: 기사 목록 CSV (`date,title,url,source`), 예시 116건 + 직접 만든 3건짜리 CSV 세 가지
- 시연 날짜/환경: 2026-10-19 · 배포본과 같은 커밋(main `894a994`)을 로컬 서버로 띄워 Chromium(Playwright)으로 시험. 작업 환경에서 github.io 접속이 막혀 있어 배포 주소 자체는 사람이 따로 열어 확인한다

## 써 본 자료
- 예시 자동 불러오기: 116 · 103 · 13 · 2 (README 기대값과 같음)
- 기사 3건짜리 CSV를 세 모양으로: 정상 머리글 / 머리글 없음 / 열 순서가 다름(`title,date,url,source`)
  - 다른 도구에서 내보낸 CSV는 머리글이 없거나 열 순서가 다른 경우가 흔해서 골랐다

## 막힌 곳 (위치→관찰→직접 확인한 증거)
1. 입력 → 머리글 없는 CSV → 첫 기사가 경고 없이 빠짐. 총 건수 3이 아니라 2, 건너뛴 줄 0, 기준일 2026-10-16 → 10-15로 하루 당겨짐
2. 입력 → 열 순서가 다른 CSV → 세 줄 모두 `날짜 형식 오류 (YYYY-MM-DD 아님: OpenAI releases …)`로 건너뜀. 상태 줄은 `분류된 결과가 없습니다 (js 1차 구현 전).`
- 원인: `js/import.js`가 첫 줄을 무조건 머리글로 버리고 칸을 0·1·2·3번 위치로만 읽음

## 바꾼 것과 이유
- `js/import.js`: 머리글의 열 이름으로 칸을 찾고(순서 무관), 첫 칸이 날짜면 머리글 없는 파일로 보고 1번 줄부터 읽음. 평소와 다르게 읽었으면 `notes`로 알림 — 조용히 고쳐 읽으면 사용자가 모르기 때문
- `js/app.js`: `notes`를 상태 줄에 표시, 0건일 때의 오래된 문구를 바꿈
- `js/README.md`: 함수 약속에 `notes` 추가 (그 팀 규칙: 약속을 바꾸면 이 문서부터)
- 판단 기준(`rules.js`)은 건드리지 않음 — 입력 읽기 문제라서
- 검증: 수정 전·후 코드를 같은 입력으로 비교. 예시 116건은 건별 주제·점수까지 같고, 머리글 없음 2건 → 3건, 열 순서 다름 0건 → 3건
