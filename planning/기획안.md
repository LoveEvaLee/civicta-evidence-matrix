## 연구 질문
신흥기술 영향평가에서 시민의 참여를 지원하는 디지털 플랫폼은 얼마나 접근 가능하고 숙의를 지원하며 시민의 의견이 실제 과학기술정책에 반영되는 과정을 얼마나 투명하게 보여 주는가?

- 차별점: '시민이 참여할 수 있었는가'(HCI)와 '참여한 의견이 정책으로 이어졌는가'(정책)의 차이를 한 표에서 본다.
- 출발점: 디지털 시민참여 도구 116개 분석(Shin et al., 2024)은 시민→정부 정보 흐름 기능보다 결정·집행의 책임성 정보를 시민에게 돌려주는 기능이 부족하다고 보고했다.

## 입력 → 처리 기준(파일) → 출력
- **입력**: 문헌 CSV (붙여넣기 · 파일 선택 · 예시 버튼 두 개)
  - 실존 문헌 16편 `data/real-literature.csv`: DOI 실재 확인, 초록 기준 코딩 초안
  - 가상 예시 12건 `data/demo-literature.csv`: 기능 시연용 모의 자료
  - 다른 입력 `data/other-input.csv`: 오류 처리 시험
- **처리 기준**: `docs/rules.js`
  - 정책 단계 4 · HCI 차원 5 · 근거 유형 · 정책 반영 근거 수준 · 검토 수준
  - 등록되지 않은 값은 추정하지 않고 **미분류**로 남기며 경고한다.
  - 문헌 하나에 주 정책 단계 1개, 주 HCI 차원 1개. 부차 측면은 `notes`
  - 정의는 `planning/분류_코드북.md`
- **처리 순서**: 읽기·줄 번호(A) → 기준 적용·경고(A) → 집계·필터(B) → 표·막대·근거 목록(B·공동) → 내보내기(B)
- **출력**: 요약 4칸, 5×4 매트릭스(칸 클릭 → 근거 문헌), HCI 차원별 막대, 문헌별 근거 표, CSV·마크다운 보고서
- **자동화(선택)**: ① 샘플 보기는 API 키 없이 AI 제안 견본 6편을 보여 준다. ② 실제 자동화는 각자 본인 API 키로 DOI → 초록 수집 → Claude 코딩 제안을 받는다. 두 방식 모두 사람이 확인·수정해 체크한 문헌만 매트릭스에 들어간다.
- **하지 않는 것**: AI 제안을 사람 확인 없이 집계, 제목 키워드로 자동 분류, DOI 진위 자동 판정, 정책 효과 추정, API 키를 저장소나 내보낸 파일에 남기기

## 이 도구에 들어간 기준과 가치판단
- **0칸의 의미.** 실존 16편에서 피드백·반영추적 행은 1칸만 채워졌다. 이것이 연구 공백인지, 16편이라는 작은 표본과 초록만 읽은 코딩의 결과인지는 이 표만으로 가릴 수 없다.
- **주 차원 하나 규칙.** Kaplan et al.(2021)은 문제설정·숙의·결과통합 세 단계를 모두 다루지만 '숙의·공론화' 한 칸에만 들어간다.
- **초록 기준 코딩의 한계.** 정책 반영 근거 수준은 초록으로 판정할 수 없어 대부분 '미코딩·판정 보류' 또는 '해당 없음'이다. 반영 근거 확인 0편은 반영이 없다는 뜻이 아니다.
- **검색 범위.** 16편은 체계적 검색 결과가 아니라 출발점 표본이다. 연구공백을 주장하려면 DB·검색식·검색일·포함/제외 기준이 필요하다.
